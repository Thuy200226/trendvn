# Deployment: installation, Docker, remote access, machine transfer

## 1. Requirements

| Component | Requirement |
|---|---|
| Operating system | Linux (tested on Ubuntu) or macOS ([MAC.md](MAC.md)). Windows: item 8 |
| Docker | Docker Engine + plugin `docker compose` v2 (Mac: Docker Desktop); Current user can run `docker` without sudo |
| Python | **3.10 and above** for agent (playwright and yt-dlp required), has `venv`. macOS only comes with 3.9: install `brew install python@3.12` or install from python.org. `./trendvn` automatically selects the latest version of Python available on the device. The remaining tools run with system python3 (3.9) |
| Browser | **Google Chrome** real (Playwright controls Chrome installed on the device, does not download packaged Chromium) |
| Disk | ≥ 4 GB free (Docker image ~2 GB; video downloaded and built gradually, cleaned periodically: [OPERATIONS.md](OPERATIONS.md)) |
| Network | Out to the internet. Want US source: a proxy/VPN for US IP |
| | Gemini API key (created by you at Google AI Studio) |

## 2. Completely fresh installation

On the source machine, clean package (no secrets, data, TikTok sessions, Python environment):

```bash
./trendvn package        # create dist/trendvn-<version>.tar.gz + .sha256, after self-test
```

Copy to new device (AirDrop, USB, scp), check `shasum -a 256 -c trendvn-*.sha256` (Mac) / `sha256sum -c …` (Linux), extract then:

```bash
tar xzf trendvn-1.6.tar.gz && cd trendvn-1.6
./trendvn install
```

`install` can be run multiple times, each time without destroying existing data. Parameters: `--no-activate` (load workflow but do not enable schedule), `--no-service` (do not install background service for agent; run `./trendvn agent run` automatically).

Eight steps of `install` (each step can be used separately): check condition → `scripts/setup_env.py` (create `.env`, generate secret once, select unused Docker network range in 172.20–172.31, do not change any keys you have set) → `./trendvn agent venv` → `./trendvn n8n build` → `./trendvn up` → `./trendvn n8n import` → `./trendvn n8n activate` → `./trendvn agent install`.

Then do 5 things only you can do (lock Gemini, log in to TikTok, set the correct destination account, wait for a video then dry-run, turn on self-posting): see settings in [README](../README.md).

## 3. Docker: what's inside

| Component | Where to run | Note |
|---|---|---|
| `worker` | container, image `trendvn/worker:<version>` build from `services/worker/` | Standard Python (no need for pip), ffmpeg, console on port 5681. Runs using your uid/gid, root filesystem is read-only, removes everything capability, `no-new-privileges`, `HEALTHCHECK` |
| `n8n` | container, image `docker.n8n.io/n8nio/n8n:<pinned-version>` | Interface at port 5680. Has healthcheck |
| `agent` | **on device, not in Docker** | Needs real Chrome, screen and TikTok login session; listen on port 5682 only on Docker bridge address (Linux) or `127.0.0.1` (Mac) |

| Resources | Name | What's in it |
|---|---|---|
| Network | `<project>_private` (private bridge, range chosen by `setup_env.py`) | Only two containers and agents can see each other |
| Volume | `<project>_n8n_data` | Account, credential, running history of n8n |
| Mounted folder | `./data/worker` → `/data` | SQLite, video, Gemini key — **the most worth backing up** |
| Mounted folder | `./n8n/workflows` → `/import` (read only) | Workflow generated by `build.py` |
| Log | json-file, self-rotating 5 × 10 MB per service | `./trendvn logs` |

Equivalent pure Docker command (when you want to do it yourself; always run in the project directory, needs `.env`):

```bash
export TRENDVN_VERSION=$(cat VERSION)     # to image with version label; omit it then use 'dev'
docker compose build worker               # = ./trendvn build
docker compose up -d --wait               # = ./trendvn up (add --build to rebuild)
docker compose ps                         # status + healthy
docker compose logs -f --tail 100 worker  # = ./trendvn logs worker -f
docker compose exec -e N8N_RUNNERS_BROKER_PORT=5690 n8n n8n list:workflow   # workflow trong n8n (= ./trendvn n8n status)
docker compose down                       # = ./trendvn down (DO NOT add -v: will delete volume n8n)
```

Two copies on one machine: put different `COMPOSE_PROJECT_NAME`, `TRENDVN_N8N_PORT`, `TRENDVN_WORKER_PORT`, `TRENDVN_AGENT_PORT` in `.env` of the second copy and install with `--no-service`.

## 4. Log in to n8n (and console) from another machine

**Short answer: yes.** By default both only open on the server itself (`127.0.0.1`), because n8n and the control panel contain the ability to post to your channel. Three ways, in order of choice:

### Method A — SSH tunnel (recommended, do not change configuration, do not open ports)

On **other device** (your laptop):

```bash
ssh -N -L 5680:127.0.0.1:5680 -L 5681:127.0.0.1:5681 <user>@<m\u00e1y-ch\u1ee7>
```

Leave that window running, then open **http://localhost:5680**(n8n) and**http://localhost:5681** (control panel) right on the laptop. No need to change anything in `.env`.

### Method B — Private VPN (Tailscale, WireGuard)

On the server, edit `.env` (replace `100.64.0.5` with the server's VPN address):

```
TRENDVN_BIND=100.64.0.5
TRENDVN_N8N_URL=http://100.64.0.5:5680
TRENDVN_N8N_HOST=100.64.0.5
TRENDVN_UI_HOSTS=100.64.0.5:5681
TRENDVN_UI_PASSWORD=<password-length-at-least-12-characters>
```

then `./trendvn up`. The ports only listen on the VPN address, so people outside the VPN cannot see it. The control panel only responds to `Host` located in `TRENDVN_UI_HOSTS` (to prevent accidental access via strange names).

### Method C — Domain name + HTTPS (only if absolutely necessary)

Place a reverse proxy (Caddy or nginx) with TLS and **private authentication** in front of port 5680/5681, keep `TRENDVN_BIND=127.0.0.1`, then:

```
TRENDVN_N8N_URL=https://n8n.ten-mien.com
TRENDVN_N8N_HOST=n8n.ten-mien.com
TRENDVN_N8N_PROTOCOL=https
TRENDVN_N8N_SECURE_COOKIE=true
TRENDVN_UI_HOSTS=dieukhien.ten-mien.com
TRENDVN_UI_PASSWORD=<password-length-at-least-12-characters>
TRENDVN_UI_HTTPS=1 # login cookie has Secure flag
```

With **nginx**, the correct domain name and guest address must be passed, otherwise the control panel does not know who the guest is:

```
location / {
    proxy_pass http://127.0.0.1:5681;
    proxy_set_header Host $host;               # required: domain name in TRENDVN_UI_HOSTS, NOT 127.0.0.1
    proxy_set_header X-Forwarded-For $remote_addr;
}
```

(Caddy does both by default.) The console considers any request with header `X-Forwarded-For`, `X-Real-IP`, `Forwarded`, `X-Forwarded-Host`, or `X-Forwarded-Proto` to be **no**must be from the machine itself, so a configurable proxy is missing `Host` also cannot open the control panel without password. Change password = restart worker = everyone must log in again; The "Log out" button in the footer ends the session right on the server.**No**set `TRENDVN_BIND=0.0.0.0` and open it directly to the Internet. The control panel only opens without password on the machine itself; with any other `Host` in `TRENDVN_UI_HOSTS` it**required** `TRENDVN_UI_PASSWORD` (login page, block wrong guess after 5 times). If you do not set a password, those hosts will be rejected. The SSH tunnel (way A) does not require a password because you enter with `localhost`.

### What you need to know when editing workflow remotely

- The first time you open n8n, it asks **to create an owner account (owner)**: email and password of your choice. This account is stored in volume `<project>_n8n_data`; it is in the backup.
- Edit and run the remote workflow **still running on the server**: Chrome, TikTok session and video are all on the server. You only control it remotely.
- Workflow calls `http://worker:8080` and `http://trendvn-agent:<port>`, two names that only exist within the project's Docker network. Therefore, **does not need to and should not package or import manual workflow** into n8n of another machine: `./trendvn install` has pre-loaded all 6 workflows and authentication information on the new machine ([N8N.md](N8N.md)).
- Do not paste key `TRENDVN_TOKEN` into the workflow: it is in the "TrendVN · Private Worker" credential created by `./trendvn n8n import`.

## 5. American source: proxy or VPN

TikTok and Instagram pay content by IP. Added to `.env`:

```
TRENDVN_US_PROXY=http://user:pass@host:port # also accept socks5: //
```

then `./trendvn agent restart`. Agent checks the country of the exit IP before each scan; if not US, these two sources are ignored and the panel states why. Only the browser collects using a proxy; Downloading videos also goes through that proxy, while your TikTok poster **no** uses a proxy.

## 6. Backup, restore, transfer

```bash
./trendvn backup                       # data/backups/trendvn-<ngdate-time>.tar.gz (0600): SQLite, Gemini key, message, .env, n8n data
./trendvn backup --with-session        # with TikTok login session
./trendvn restore data/backups/<file>  # on the installed directory; Ask for confirmation before overwriting
```

**Switch to new device** (this order avoids two devices posting to the same channel):

```bash
# OLD Machine
./trendvn n8n deactivate                 # turns off the calendar in advance, so that both devices do not post at the same time
./trendvn backup --with-session
./trendvn uninstall
# NEW machine
tar xzf trendvn-1.6.tar.gz && cd trendvn-1.6
./trendvn install --no-activate
./trendvn restore <b\u1ea3n sao l\u01b0u>          # data, n8n, TikTok session; Auto schedule is turned OFF
./trendvn doctor
./trendvn tiktok login                   # carried over may be asked again by TikTok
./trendvn tiktok dry-run
./trendvn n8n activate                   # turn on the calendar on the new device when everything is fine
```

> **Only one device running automatically for one TikTok account.** Two devices posting to the same channel will post duplicates because they do not share a queue.

`N8N_ENCRYPTION_KEY` in `.env` encrypts information in n8n: if this key is lost, the credential stored in n8n cannot be read. Backup `.env` with data (`backup` did this).

## 7. Starts automatically with the machine

- Container has `restart: unless-stopped`: automatically mounts when Docker mounts.
- Agent runs under `systemd --user` (Linux) or `launchd` (Mac). Linux: let it run as soon as the computer boots, even if no one has logged in: `sudo loginctl enable-linger $USER`. Mac: runs when you log in.
- Agent needs the project's Docker created network to listen on the bridge address; If it's in front of Docker, it retries every 15 seconds.

## 8. macOS and Windows

- **macOS:** `install` recognizes macOS: find Chrome in `/Applications`, install agent with `launchd` (`~/Library/LaunchAgents/vn.trendvn.agent.plist`, runs with `caffeinate` so Mac doesn't sleep while working). Docker Desktop runs containers in a virtual machine so there is no bridge address like Linux: `setup_env.py` sets itself `TRENDVN_AGENT_BIND=127.0.0.1` and `TRENDVN_AGENT_HOSTREF=host-gateway` so that it can call the agent on Mac. Step-by-step instructions: [MAC.md](MAC.md). Runs for real on Linux: clean install from the package (remove background services step), n8n call agent, backup and restore. Only static check: systemd/launchd background service (generated content is valid, pointing to the correct file). Haven't tested it on a real Mac: the entire macOS part (launchd, `host-gateway` of Docker Desktop, Python 3.10+ via Homebrew).
- **Windows:** uses WSL2 (Ubuntu) to run completely like Linux, but real Chrome must run in WSL (install `google-chrome` in Ubuntu) and needs WSLg to display the login window.

## 9. Update version

Extract the new version **overwriting the running directory** (the packaged version does not contain `.env` and `data/` so they are kept intact), then update:

```bash
cd ~/trendvn                                              # running directory
tar xzf ~/Downloads/trendvn-<phi\u00ean-b\u1ea3n-m\u1edbi>.tar.gz --strip-components=1   # files of the old version that are no longer used in the new version can be deleted if desired
./trendvn update                  # rebuild image, generate + reload workflow (schedule remains the same), update agent Python package, reboot, doctor
./trendvn tiktok dry-run          # always try again after updating, because TikTok may change its appearance
```

If `doctor` reports "Worker is the correct version of the code" error: the container is still running the old image, run `./trendvn update`.

## 10. Uninstall

```bash
./trendvn uninstall           # stops services and containers, HOLDS data
./trendvn uninstall --purge   # deletes both data, TikTok sessions, n8n (asks for confirmation, does not undo)
```

## 11. Switch from version 1.2 (old folder) to new version (1.3 or later) on the same device

From version 1.3, the directory layout has been changed (old → new path table is in [CHANGELOG](../CHANGELOG.md)). Docker identifies a system by **projectname** (`trendvn`), not by directory,
so version 1.2 is running and the newly extracted version uses **with the same name**: `./trendvn` refuses to stop or overwrite the other folder's container (`guard_project`). Switch with one command, run in folder **new**
(just unpacked, not installed):

```bash
tar xzf trendvn-1.6.tar.gz && cd trendvn-1.6
./trendvn migrate <th\u01b0-m\u1ee5c-1.2>
```

`migrate` check everything **before**when stopping anything (old folder is indeed version 1.2, nothing is running, new folder is empty), then: backup with `backup.sh` old → stop agent and old container (loss of service for a few minutes) → copy `.env`, `runtime/` → `data/worker`, `agent_data/` → `data/agent` (keep TikTok session, remove Chrome cache) → `./trendvn install --no-activate` → compare video numbers by status. The status you are in**keep the same**: n8n calendar is still on while on, off is still off, "Auto post" and all settings remain unchanged. Directory 1.2 is kept as backup; If any step fails, `migrate` Pre-printed commands to return to the old directory.

Why use the old `.env` correctly: `docker compose down` retains volume n8n, and n8n refuses to boot if the encryption key is different from the key that created that volume. (Going by hand is also possible: copy the old `.env` into the new folder **before** `./trendvn install`, then the backup `./trendvn restore`.)

Want to run two versions of **in parallel** for comparison: in `.env` of the new version, set `COMPOSE_PROJECT_NAME`, `TRENDVN_N8N_PORT`, `TRENDVN_WORKER_PORT`, `TRENDVN_AGENT_PORT` differently from the old version, and install with `--no-service` (only an agent can hold the background service `trendvn-agent`). Don't let two versions turn on the same TikTok channel.
